# Test the Companion through stable seams and native builds

Companion development proceeds test-first through four stable seams: the Rust engine's snapshot/command/subscription interface using a real temporary SQLite database and filesystem with a deterministic Shadow Cloud adapter; the server's Companion HTTP contract; React presentation against engine snapshots and commands; and packaged native smoke behavior. Tests use opaque synthetic save contents and inject interrupted operations, lost responses, concurrent devices, file mutations, missed watcher events, restarts, permission and disk failures, folder conflicts, revoked sessions, and protocol mismatches. Deterministic model tests protect invariants including no duplicate submission, no overwrite, no lost Turn candidate, monotonic publication cursors, and account isolation.

Linux is the available human-operated acceptance host, and its application webview is exercised with computer-driven interaction wherever the available tooling can control it. A development-only deterministic scenario harness presents synthetic Campaigns and controllable states through the production React-to-engine boundary so that onboarding, offline behavior, conflicts, countdowns, catch-up, and failures can all be inspected without changing a live Campaign; the harness is excluded from release bundles. Native CI still builds and launches Windows, macOS, and Linux packages and runs platform integration checks on each. Browser-driven interaction cannot establish confidence in operating-system surfaces such as installers, the tray, credential vaults, native notifications, file pickers, or autostart, so those retain targeted native automation and a Linux manual spot check rather than being represented as browser coverage.
