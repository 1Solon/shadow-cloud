# Store companion state in SQLite and credentials in the OS vault

The Desktop companion stores Campaign ownership, content identities, Turn candidates, Ignored candidates, operations, and migrations in an embedded transactional SQLite database, while its Device-session refresh secret lives separately in the operating system's credential vault. The database is not encrypted because it contains neither credentials nor save contents; it receives user-only filesystem permissions instead. If a secure vault is unavailable, the credential remains in memory and the player must sign in again after quitting rather than falling back to plaintext storage. JSON or Tauri plugin storage would be simpler initially but cannot safely coordinate the provenance ledger and recoverable operation state without rebuilding database semantics, and storing credentials alongside ordinary state would widen their exposure.
